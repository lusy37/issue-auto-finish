# 配置、知识读写与文件保存修复计划

日期：2026-09-12。状态：已实施，本机验收通过。

本计划处理审核中的问题二、问题三和问题五。目标是让配置实际生效、项目知识始终来自同一来源，并降低保存中断或文件损坏造成的数据损失。

核对基线：`main`，提交 `9f473db`，包含工作区已有的首页与详情页拆分。当前阶段循环使用原有 `Orchestrator`；此前临时 LangGraph 改动的失败结果不能直接作为本次实施基线，应重新验证。

## 一、实施口径

沿用现有 Vue 设置页、Express 接口、本地 JSON 和 `atomically`。保留 `orchestration` 的纯状态转换与 `orchestrator` 的副作用分层。所有运行数据使用 `.iaf-mini/` 或显式配置的新目录，不读取或迁移原 `data/`。

本计划按用户最新选择实施：Web 固定开启，审核、知识引用和蒸馏保留用户开关，均默认开启。当前产品规则如下：

| 配置 | 实现行为 |
| --- | --- |
| `VERIFY_FIX_LOOP_ENABLED` | 保留，默认开启，在现有设置页提供开关；关闭后验证失败即停止自动修复，等待人工处理 |
| `VERIFY_FIX_MAX_ITERATIONS` | 保留，默认 3，范围 1～10，在设置页使用数字输入；表示初次验证失败后最多追加的自动修复轮数 |
| `WEB_ENABLED` | Web 固定开启，不在设置页提供开关；清理无效的关闭配置，Web 地址和端口仍按原配置处理 |
| `REVIEW_ENABLED` | 保留，默认 true；设置页提供“启用计划审核”。关闭后，新生成的完整计划保存成功即可自动继续实现，记录“按配置自动通过”，不冒充人工审核 |
| `KNOWLEDGE_ENABLED` | 保留，默认 true；设置页提供“任务引用知识与经验”。关闭后，AI 任务不注入附加知识、经验及规则；资料管理、历史内容和任务必需的项目执行配置仍可使用 |
| `DISTILL_ENABLED` | 保留，默认 true；设置页提供“启用经验蒸馏”。关闭后拒绝新的蒸馏执行，不调用模型生成新经验；保留原有知识、日记和运行历史 |
| 其他有效配置 | 保持原有语义，包括预览、待办检查、知识路径和蒸馏阈值 |

设置保存后重启生效。运行中的服务继续使用启动时的配置，重启后继续执行的任务使用新的服务配置，同时保留已有修复历史，不能靠重启重置次数。浏览器验收仍为必需阶段。

三个开关分别控制审核等待、知识引用和新经验生成，不互相隐式改值。知识引用关闭时仍可管理资料、执行已开启的蒸馏，产出的经验暂不进入任务上下文；蒸馏关闭时，知识引用仍可使用已有经验。日记采集作为任务执行记录继续保留，不属于模型蒸馏开关的控制范围。

关闭审核只对重启后新进入审核节点的计划生效；已经等待人工审核的任务保留等待状态，需明确执行通过或重做操作。重新生成计划后按当前配置处理。审核开启时沿用现有人工审核与自动审核标签规则；标签规则仅在审核开启时参与判断。

本次不实现配置热更新、数据库迁移、跨文件事务、知识索引自动重建，也不处理另行发现的 Markdown 渲染安全问题。

## 二、问题五：先补齐可靠保存

### 改动位置

- `src/utils/atomicFile.ts`：抽取共用的原子文本写入，JSON 写入继续调用它。
- `src/knowledge/KnowledgeStore.ts`：知识正文、索引、缓存提交顺序及损坏文件处理。
- `src/supplement/SupplementStore.ts`：补充资料保存及读取错误处理。
- `src/knowledge/ProjectProfile.ts`、`src/web/routes/setup.ts`：分别接入 JSON 和配置文本的原子保存。

### 实施步骤

1. 复用现有 `atomically` 重试、替换和清理机制，避免新增一套临时文件规则。JSON 序列化在开始写入前完成，保留底层错误信息。
2. 将上述写入改为临时文件写完整后替换目标文件；同步调用方式保持一致。
3. 知识索引修改基于深拷贝的新对象，成功落盘后才替换内存缓存。新增、更新、删除及 `lastAnalyzedAt` 都遵守同一规则。
4. 区分不存在和损坏：首次使用且索引不存在时可以初始化空索引；索引损坏或结构不合法时返回明确错误，不返回空列表，不自动覆盖。补充资料读取错误也不能被当作“尚未填写”。
5. 区分没有索引的全新目录与已有正文的异常目录：如果索引缺失但已有正文文件，应报告异常并保留数据，不能直接初始化空索引。
6. 新增时先保存正文，再保存索引。删除时先保存移除记录后的索引，再清理正文；若正文清理失败，记录可定位的清理错误，保留已提交的删除结果，不假装索引尚未改变。
7. 索引仍引用某条目而正文缺失或无法读取时，明确报告损坏，不能用空字符串冒充有效正文。

### 保证与边界

单个文件替换失败时，原有完整文件应保留；索引保存失败时，不发布新的内存索引。索引损坏时，原文件和正文均保留，页面显示可定位的错误。

正文和索引是两个文件，各自原子写入不等于整体事务。例如更新正文成功、更新索引失败时，正文可能已经是新内容。此时必须报告实际失败，保留可恢复的文件，不能宣称全部回滚。新增失败留下的无索引正文也不自动删除或导入，避免误处理资料。

## 三、问题三：统一项目知识的路径与更新语义

### 改动位置

- `src/knowledge/KnowledgeLoader.ts`：有效路径、加载状态及缓存更新。
- `src/knowledge/ProjectProfile.ts`：资料读取与局部字段更新。
- 启动仍由 `src/index.ts` 调用加载器；加载器为单实例服务保存有效来源，资料接口沿用它，无需在 WebServer 和路由层重复传递路径。

### 实施步骤

1. 启动时统一解析知识文件路径：显式 `KNOWLEDGE_PATH` 优先，否则使用 `DATA_DIR/knowledge/knowledge.json`。后续读取、重新加载、保存及缓存回退均沿用此路径。
2. 默认路径首次不存在时允许使用默认资料，并在首次保存时创建。显式配置路径不存在、文件损坏或无读取权限时，给出明确错误，不回退到另一位置。
3. 将不带参数的 `loadKnowledge()` 明确定义为沿用当前有效来源；查询页面不能悄悄切换 AI 使用的知识来源。
4. 保存前读取当前完整知识，克隆后只更新表单允许编辑的字段。保留架构说明、已知问题、其他工具链配置和未编辑字段。
5. 校验新内容后原子写入同一个目标文件，成功后再更新缓存。加载或保存失败时保留最近一次成功缓存，同时向本次调用返回错误，不能把失败伪装成成功。
6. 资料保存成功后页面刷新可见；知识引用开启时，之后构建的 AI 提示词使用新知识，已经发出的 AI 请求不追溯修改。知识引用关闭时，资料保存仍正常，但不把附加知识注入任务上下文。
7. 明确区分项目执行配置与可选知识上下文：安装、构建和测试命令等任务所需配置不能因为关闭知识引用而被清空或偷偷换成默认命令。管理接口的读取不能绕过任务上下文的禁用判断。

### 预期结果

自定义文件 A 被加载后，打开资料页面仍读取 A，保存也只写 A。只修改项目说明不会清空架构说明或已知问题。默认位置的文件 B 不会因为这次操作被创建或覆盖。

## 四、问题二：让可配置项贯通设置与执行

### 改动位置

- `src/config-schema.ts`、`src/config.ts`、`env.example`：有效配置、校验和旧配置提示。
- `src/web/routes/setup.ts`、`src/web/frontend/src/components/SettingsPanel.vue`：沿用现有表单与 API，补充审核、知识引用、蒸馏和自动修复设置。
- `src/orchestration/Transitions.ts`、`src/orchestrator/steps/PhaseLoopStep.ts`：根据服务配置构造修复规则。
- `src/phases/VerifyPhase.ts`：自动修复关闭时的明确失败意图。
- `src/index.ts`、`src/phases/BasePhase.ts`、`src/prompts/templates.ts`、`src/orchestrator/PipelineOrchestrator.ts`：核对知识引用入口，区分任务执行配置与可选知识注入。
- `src/distill/DistillScheduler.ts`、`src/web/routes/distill.ts`：在实际执行入口检查蒸馏开关，状态接口返回真实启用状态。
- `src/web/routes/api.ts`、前端状态类型、`KnowledgePanel.vue`、`DistillPanel.vue` 及审核状态展示：保留三个有效开关的状态回显，展示配置禁用原因及自动通过来源。
- 如涉及导出调整，同步更新 `src/orchestration/index.ts` 和实际调用点。

### 实施步骤

1. 为最大修复次数补数字输入，为审核、知识引用、蒸馏及自动修复状态补勾选控件；后端沿用已有的布尔及 1～10 整数校验。关闭自动修复时可以禁用次数输入，但保留用户填写值。
2. 设置 API 增加上述五个字段的读取、保存和默认值映射；沿用“已保存，请重启生效”的提示。设置页展示的是已保存值，系统状态展示的是当前服务实际使用的值。
3. 使用纯函数按配置生成转换规则，替代生产调用中的固定 `maxIterations: 3`。自动修复次数与同阶段错误重试次数、编排器防无限循环上限分别处理，不能混用。
4. 关闭自动修复时，验证失败返回需要人工处理的失败意图，保留失败原因与报告，不回到 build，不绕过 verify，不进入 uat 或交付。
5. 仅对 `WEB_ENABLED` 清理无效的关闭配置及相关示例、类型和快照。旧值为 true 时提示清理，false 时明确说明 Web 固定开启并给出迁移提示，不再声称可以关闭 Web。
6. 保留 review 节点和原有审核历史结构，复用现有审核动作处理配置关闭后的自动通过。计划仍先完整持久化，审批来源和页面文案应区分人工通过、标签自动通过及配置关闭后的自动通过。已有等待审核的任务不会因重启自动推进。
7. 在任务知识上下文的实际构建入口检查 `KNOWLEDGE_ENABLED`，同时覆盖阶段提示词、附加经验与规则等读取渠道。关闭时资料管理可用，页面提示“任务知识引用已关闭”；安装和测试等必需命令继续按项目执行配置读取。
8. 在蒸馏接口和执行入口检查 `DISTILL_ENABLED`，包括强制执行选项，避免直接请求 API 绕过界面。关闭时按钮禁用、状态为 disabled，请求返回明确的功能关闭错误，模型调用次数为零；日记和历史查询继续可用。当前蒸馏为手动执行，不新增自动调度。
9. 现有手动重试入口继续可用。最大次数基于已有修复历史计算，重启恢复不能重新获得完整修复额度。

### 次数示例

`VERIFY_FIX_MAX_ITERATIONS=1` 时，初次 build → verify 失败后，最多再执行一次 build → verify。第二次 verify 仍失败就停止自动处理；若成功，则继续正式 uat。

优先扩展已有测试，只为缺少覆盖的行为新增测试文件。故障测试使用临时的新数据目录，不修改用户当前数据；浏览器回归使用模拟平台及 AI。

| 知识引用关闭 | AI 上下文不包含附加知识、经验和规则，项目执行命令保持有效，资料管理和保存可用 |

| 自动修复关闭 | 验证失败即停止，不执行第二次 build，不进入 uat 或交付 |

| 设置保存与服务重启 | 保存能回读，当前服务配置不变；重启后新配置实际参与执行 |

| 显式知识路径缺失或损坏 | 明确提示错误，不回退到默认文件，不覆盖最近成功缓存 |
| 临时写入失败、替换失败 | 目标文件保留旧的完整内容；错误传递到调用方 |
| 索引写入失败 | 不发布修改后的内存索引；报告实际失败阶段 |
| 索引损坏或缺失但已有正文 | 读取/修改明确失败，原索引及正文不被空数据覆盖 |
| 索引存在但正文丢失 | 报告损坏，不返回空正文冒充成功 |
| 正文已写入、索引提交失败 | 验证部分提交边界，保留可恢复文件，不声称整体回滚 |
| 删除后的正文清理失败 | 索引删除结果一致，记录清理错误，后续查询不出现幽灵条目 |
| 补充资料损坏 | 页面或任务获得明确错误，不继续当作未填写 |

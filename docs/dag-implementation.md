# 单 Issue 内部 DAG 实施记录

本次实现采用状态一致性与恢复修订版：一个草稿创建一个 Issue，统一审核结构化计划，在 build 内执行任务图，汇总后验证与浏览器验收，更新这个 Issue 唯一的 PR。外层仍为 plan、review、build、verify、uat，没有第二套执行模式，也不自动合并 PR。

## 代码入口与事务边界

| 职责 | 实现入口 |
| --- | --- |
| 单草稿、创建意图、平台标记核对 | `src/demand/DraftService.ts` |
| 格式、计划校验、执行身份与凭证 | `src/dag/contracts.ts` |
| 不可变计划、聚合状态事务 | `src/dag/IssueRunStore.ts` |
| 父状态与历史的统一转换 | `src/orchestrator/TrackerStateStore.ts` |
| 任务派发、依赖、变基、串行合并 | `src/dag/TaskGraphExecutor.ts` |
| 两个 build 入口、候选提交及验收凭证 | `src/orchestrator/DagPhaseRunner.ts` |
| SDK 额度、受管理 worker | `src/ai-runner/ManagedCodexRunner.ts`、`sdk-worker.ts` |
| 调用登记与过期结果隔离 | `src/dag/ScopedRunner.ts` |
| 停止、重试、恢复、目录清理 | `src/orchestrator/PipelineOrchestrator.ts` |
| 已验收提交的推送、唯一 PR、Issue 回写 | `src/dag/DeliveryService.ts` |
| 任务与尝试展示 | `src/web/frontend/src/components/TaskGraphPanel.vue` |

`orchestration` 保留纯状态转换，`orchestrator` 负责调用与副作用。`IssueTracker` 是聚合状态的访问及展示适配层，不再另外保存一份 tracker 权威文件。

每个 Issue 的 `DATA_DIR/issues/<编号>/run.json` 是唯一运行状态。`plans/<revision>.json` 保存不可变计划，包含父需求、补充资料、验收标准、任务定义和内容摘要。历史、父阶段、进度、任务、停止意图、预算、验收、交付身份在同一次同步事务中计算并原子替换；替换成功后才更新缓存并发事件。读接口返回副本，写入失败阻断该 Issue 的新调度和合并。

计划文件先写完整，再更新运行状态中的引用。崩溃留下的未引用版本不执行，也不覆盖；新版本继续递增。Markdown 和 `artifacts/` 下的进度、报告仅供展示及诊断，不是第二份运行状态。

## 状态转换和执行身份

| 场景 | 原状态／证据 | 转换或约束 |
| --- | --- | --- |
| 计划完成 | SDK 成功且 JSON 校验通过 | 保存新版本，进入统一审核 |
| 批准、跳过、自动批准 | 当前版本且正在等待审核 | 同一事务批准该版本 |
| 驳回 | 当前版本且正在等待审核 | 保存完整计划快照和反馈，重新规划 |
| 旧页面批准或驳回 | 版本不符或已不在审核 | HTTP 409，不更新状态 |
| 任务可执行 | 全部前置任务已确认合并 | 创建独立尝试、起点和目录，申请 AI 额度 |
| SDK 最终失败 | 即使已有 AI 中间提交 | 无成功凭证，不进入合并队列 |
| SDK 最终成功 | 服务端保存结果提交 | 等待合并；无变化也保存明确成功凭证 |
| 首个任务失败 | 仍有在途任务 | 停止新派发和新合并，收齐结果后只报一次父失败 |
| verify 失败／有效 UAT 断言失败 | 剩余共享修复轮数大于 0 | build 的 repair-integration，随后重新 verify、UAT |
| 缺报告、环境故障、无有效变化、无法解释的 Git 状态 | 无可靠验收或恢复依据 | 人工处理，禁止猜测性交付 |
| 暂停／取消／完整重做 | 用户控制请求 | 停止意图先落盘，再取消排队、中止并等待进程退出 |
| 普通重试 | 有已确认的任务结果 | 新 dispatchId；先合并已有结果，再执行缺失任务 |
| 完整重做 | 原 PR 未关闭、未合并 | 新 buildGeneration 和预算；计划版本继续递增，PR 身份保留 |

每次调用都携带 `issueNumber + planRevision + buildGeneration + dispatchId + taskId + attemptNo + callId`。在状态锁内检查版本和身份，同一阶段被新调用替代的旧结果也不能采用。历史成功凭证由恢复流程显式复用，不能仅凭分支上存在提交认为任务完成。

控制接口返回落盘后的状态、版本、计划版本、构建轮次和停止意图。计划 Markdown 从生成时起只读；普通重试直接使用批准计划里的需求快照，显式重新规划或完整重做才读取新的需求。

## Git 合并和重启恢复

1. 保存任务起点、目录、分支和调用身份，再启动执行。
2. SDK 最终成功后，服务端生成结果提交，持久化成功凭证及无变化标志。
3. 保存变基前结果 SHA、集成起点 SHA、合并操作标识，再执行变基。
4. 冲突修复先持久化扣除额度，再申请 AI；每个任务、每个构建轮次最多两次。
5. 保存变基后结果 SHA 和预期集成起点，再快进合并这个确切 SHA。
6. 保存集成前后 SHA 和已合并状态，才解除后继任务的依赖。

变基中或变基后尚未保存结果时中断，从已记录的变基前提交恢复；不直接信任当前任务分支 HEAD。快进合并后状态尚未落盘时中断，核对已记录结果 SHA 与集成 HEAD 后补齐凭证。无法解释的提交或仍存活的孤儿调用转人工核对，不抢占目录、不重复启动替代执行。

启动先统一检查聚合、计划和草稿格式，再处理停止意图、旧调用、临时文件及 Git 凭证。暂停、取消和人工失败不会自动继续。普通重试、暂停继续和重启都不会清零已用额度；未知执行需要重新发起 AI 时也消耗剩余普通预算。

## 并发、预算和工作目录

| 配置 | 默认 | 确切含义 |
| --- | --- | --- |
| `MAX_CONCURRENT_ISSUES` | 1 | 同时驱动的父 Issue 数量，正整数 |
| `AI_MAX_CONCURRENCY` | 4 | 1～32，全部官方 SDK 调用共享，包含草稿、计划、任务、验证、各种修复和蒸馏 |
| `MAX_RETRIES` | 3 | 首次执行之外允许的自动重试次数；0 不自动重试，1 最多追加一次 |
| `VERIFY_FIX_LOOP_ENABLED` | true | verify 与有效 UAT 断言失败是否自动修复 |
| `VERIFY_FIX_MAX_ITERATIONS` | 3 | 两类失败共用的集成修复轮数，1～10 |
| 工作目录保留配置 | 7 天 | 复用现有清理开关、保留期与扫描间隔 |

没有 `TASK_MAX_CONCURRENCY`。上述用户配置接入设置页，保存后重启生效。每个父 Issue 有独立分支、目录、会话、状态和预览端口；共享仓库锁只覆盖必要 Git 操作，等待锁可取消，不包住 AI 调用。

所有 SDK 调用通过轻量 Node worker 使用官方 SDK，IPC 仅传工作台事件和结果，不重建 Codex CLI 或 JSONL 解析。收到结果仍等待 worker 退出，之后才释放 AI 额度；任务进入合并队列时不占 AI 额度，冲突修复重新申请。

父目录与短名子任务目录位于工作区根目录同级，目录和分支只由服务端生成。每次尝试登记归属；每个 worktree 独立安装依赖，集成锁文件变化后重新安装。清理检查实际路径、活动任务、恢复和进程引用；暂停或退出未确认的目录保持隔离。正常退出及中止统一使用进程工具，包含 Git、安装、测试和预览。

## 验收与唯一交付

浏览器测试准备放在 build 收尾。准备、安装或修复产生的有效仓库内容统一生成候选提交；计划、运行状态和验收报告写入数据目录，不进入目标仓库提交。

verify 和实际 Playwright UAT 都绑定候选 SHA，检查前后必须 HEAD 相同、工作目录干净。UAT 必须本次退出码与有效报告通过，模型文字或旧报告不能代替。交付前再次检查任务全部合并、两份凭证一致、HEAD 一致且无未验收修改。交付步骤不 `git add`、不新增提交；已删除阶段自动提交和提前创建 PR 的入口。

草稿及 PR 在 POST 前保存创建意图，结果未知时只能查询核对稳定标记。空结果、查询失败、多匹配、仓库或分支不符均不能重新开放创建；手工 Issue 编号也须由平台验证。推送、PR 关联和 Issue 回写各自保存进度；回写响应丢失同样保持未知，查到原标记后补齐。

PR 身份跨完整重做保留。开放 PR 继续使用；关闭 PR 要求先重开原 PR；已合并后拒绝重做，后续需求新建 Issue。取消和重做不删除已发布分支。非快进更新仅能在验收之后，以记录的远端 SHA 为 lease；出现未记录的人工远端变更时拒绝覆盖。

## 数据格式和重新初始化

新格式分别为 `iaf-mini/issue-run/v2`、`iaf-mini/task-plan/v2`、`iaf-mini/draft/v2`。不兼容或迁移旧任务、旧草稿；启动错误会指出具体文件和重新初始化方法，保留原文件。运行数据从不读取或写回仓库原 `data/`。

需要重新初始化时，先停止原服务并确认任务进程退出，再选择新的 `DATA_DIR` 和工作目录，或归档旧运行目录后初始化。旧状态仍需恢复时保留原目录及原版本程序，不能在活动目录上直接删除数据。

演示使用新的 `.iaf-mini/demo-dag-v2`，原演示目录保留。演示的 AI 和 GitHub 为模拟，真实执行 Git、落盘和浏览器，生产执行器没有模拟模式开关。
